Loyiha: Flowgorithm'da "Login va parol tekshirish tizimi"

Login-parol tizimining maqsadi va ishlash mantig'i; oldindan belgilangan login va parol bilan solishtirish; AND bilan ikki shartni birga tekshirish; xato urinishlarni hisoblash va 3 urinishdan keyin bloklash; While sikli va Boolean bayroq; xavfsizlik nuqtai nazaridan tahlil; test qilish.

1 dars · amaliy
📄 PDF yuklab olish

🎯 Bu loyihada nimani o'rganasiz

  • Autentifikatsiya (shaxsni tasdiqlash) mantig'ini;
  • Matnlarni solishtirish va AND bilan ikki shartni birga tekshirishni;
  • Urinishlar hisoblagichi bilan 3 marta xatodan keyin bloklashni;
  • Sikldan ikki xil sabab bilan chiqish: muvaffaqiyat yoki limit tugashi;
  • Dasturni xavfsizlik nuqtai nazaridan tahlil qilishni (14-mavzu bilan bog'lab).

#1-bosqich: rejalashtirish

Telefoningiz, Telegram, kundalik.com — hammasi kirishda login va parol so'raydi. Bizning tizim:

TalabQanday amalga oshiriladi
To'g'ri login va parol saqlanaditogriLogin = "admin", togriParol = "Qalam-2026!"
Foydalanuvchi ikkalasini kiritadiInput login, Input parol
Ikkalasi ham mos bo'lsa — kirishlogin == togriLogin and parol == togriParol
Xato bo'lsa — qolgan urinishlar soniurinish = urinish + 1, 3 - urinish
3 marta xato — bloklashSikl sharti: urinish < 3
O'xshatish: telefon ekran qulfiTelefon PIN-kodini bir necha marta noto'g'ri tersangiz, u "30 soniyadan keyin urinib ko'ring" deydi. Bu cheklov bo'lmasa, o'g'ri 0000 dan 9999 gacha barcha 10 000 variantni sinab chiqardi (brute force). Urinishlar limiti — oddiy, lekin juda kuchli himoya.

#2-bosqich: blok-sxema

Sikl ikki holatda tugashi kerak: kirdi (muvaffaqiyat) yoki urinishlar tugadi. Buning uchun Boolean bayroq kirdi va hisoblagich urinish ni birga ishlatamiz:

login.fprg
Main
DeclareString login, parol, togriLogin, togriParol
DeclareInteger urinish
DeclareBoolean kirdi
AssigntogriLogin = "admin"
AssigntogriParol = "Qalam-2026!"
Assignurinish = 0
Assignkirdi = false
While urinish < 3 and not kirdi
Output"Login:"
Inputlogin
Output"Parol:"
Inputparol
login == togriLogin and parol == togriParol
Assignurinish = urinish + 1
Output"❌ Xato! Qoldi: " & (3 - urinish)
Assignkirdi = true
kirdi
Output"🔒 Akkaunt bloklandi!"
Output"✅ Xush kelibsiz, " & login & "!"
End

Mantiqni tahlil qilamiz

  • Sikl sharti urinish < 3 and not kirdi: "urinish qolgan va hali kirilmagan ekan — so'rayver". Ikkalasidan biri buzilsa — chiqamiz.
  • Sikldan keyingi If: nima uchun chiqdik? kirdi rost bo'lsa — muvaffaqiyat; aks holda urinishlar tugagan.
  • AND muhim: faqat login to'g'ri, parol xato bo'lsa — kirish yo'q.
  • Matn taqqoslash harf registriga sezgir: "Admin" != "admin". Parol uchun bu to'g'ri xatti-harakat.

#Python va brauzer versiyasi

login.py
TOGRI_LOGIN = "admin"
TOGRI_PAROL = "Qalam-2026!"
urinish = 0
kirdi = False

while urinish < 3 and not kirdi:
    login = input("Login: ")
    parol = input("Parol: ")
    if login == TOGRI_LOGIN and parol == TOGRI_PAROL:
        kirdi = True
    else:
        urinish += 1
        print("❌ Xato! Qoldi:", 3 - urinish)

if kirdi:
    print(f"✅ Xush kelibsiz, {login}!")
else:
    print("🔒 Akkaunt bloklandi!")

#Xavfsizlik tahlili: real tizimlar qanday ishlaydi?

Bizning o'quv dasturimizda parol ochiq holda dastur ichida yozilgan. Haqiqiy tizimlarda bu katta xato bo'lardi:

Nega xabar umumiy bo'lishi kerak?Agar tizim "Bunday login yo'q" desa, xaker qaysi loginlar mavjudligini bilib oladi va faqat ularning parolini terishga kirishadi. Bizning dasturimiz ham umumiy "Xato!" xabarini beradi — to'g'ri yo'l.

#Kengaytmalar

  1. Bir nechta foydalanuvchi: 3 ta login-parol jufti (OR bilan): (login == "ali" and parol == "...") or (login == "vali" and ...).
  2. Ro'yxatdan o'tish: avval foydalanuvchi o'z parolini yaratadi — parol kamida 8 belgi (Len(parol) >= 8) bo'lmaguncha qayta so'rash (Do).
  3. Parolni tasdiqlash: yangi parol ikki marta kiritiladi va mos kelishi tekshiriladi.
  4. Bankomat bilan birlashtirish: 24-loyihaga PIN-kod qismini qo'shing — kirgandan keyingina menyu ochiladi.
  5. Kuchli parol generatori (3-loyiha): Random va ToChar bilan 12 belgili tasodifiy parol yaratish.

#Ko'p uchraydigan xatolar

  • ❌ or ishlatish → ✅ Faqat login to'g'ri bo'lsa ham kirib ketadi! and kerak.
  • ❌ urinish = urinish + 1 ni True tarmoqqa qo'yish → ✅ Faqat xato urinish sanaladi.
  • ❌ Sikl sharti faqat urinish < 3 → ✅ To'g'ri kirgandan keyin ham login so'rayveradi; and not kirdi.
  • ❌ Sikldan keyin tekshirmasdan "Xush kelibsiz" chiqarish → ✅ If kirdi.

#O'zingizni tekshiring

Login va parol ikkalasi ham to'g'ri bo'lishini tekshirish uchun qaysi operator?

  1. or
  2. not
  3. and
  4. &

AND — ikkala shart ham rost bo'lishi kerak.

urinish = 2, kirdi = false. urinish < 3 and not kirdi = ?

  1. true — yana bir urinish bor
  2. false
  3. 2
  4. Xato

2 < 3 rost, not false = true → true AND true.

Urinishlar limitining asosiy maqsadi?

  1. Dasturni tezlashtirish
  2. Xotirani tejash
  3. Chiroyli ko'rinish
  4. Parolni ko'r-ko'rona terib topishdan (brute force) himoya

Limitsiz har bir variantni sinab ko'rish mumkin bo'lardi.
