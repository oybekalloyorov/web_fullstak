Versiyalarni boshqarish tizimi (VCS — Version Control System) bu muammoni hal qiladi: bitta papka, lekin uning har bir muhim holati "suratga olinib" saqlanadi. Istalgan vaqtda istalgan holatga qaytish, nima o'zgarganini ko'rish, bir necha kishi bilan birga ishlash mumkin.

O'xshatish: o'yindagi "saqlash nuqtalari" Kompyuter o'yinida qiyin bosqichdan oldin "Save" qilasiz. Yutqazsangiz — boshidan emas, saqlangan joydan davom etasiz. Git'dagi har bir commit — xuddi shunday saqlash nuqtasi, faqat har biriga izoh yoziladi: "Bosh sahifa qo'shildi", "Xato tuzatildi".

#1-qadam: o'rnatish va sozlash

  1. git-scm.com dan Git'ni yuklab o'rnating (Windows uchun barcha sozlamalarni standart qoldiring). U bilan birga Git Bash terminali keladi.
  2. github.com → Sign up. Foydalanuvchi nomini jiddiy tanlang (masalan, alivaliyev-dev) — bu sizning kelajakdagi portfoliongiz manzili.
  3. Git'ga ismingiz va emailingizni bir marta aytib qo'ying (GitHub'dagi email bilan bir xil):
Git Bash
git config --global user.name "Ali Valiyev"
git config --global user.email "ali.valiyev@gmail.com"
git config --global init.defaultBranch main
git --version          # tekshirish: git version 2.4x...

#2-qadam: lokal repository — init, add, commit

Birinchi repository
mkdir portfolio          # papka yaratish
cd portfolio             # papkaga kirish
git init                 # Git'ni yoqish → yashirin .git papka paydo bo'ladi

# index.html va README.md fayllarini yarating (VS Code yoki Bloknotda)

git status               # holatni ko'rish: qizil — kuzatilmagan fayllar
git add index.html       # bitta faylni tayyorlov zonasiga
git add .                # yoki barcha o'zgargan fayllarni
git status               # yashil — commit'ga tayyor
git commit -m "Portfolio: birinchi sahifa va README"
git log --oneline        # tarix
git log --oneline natijasi
a3f9c21 (HEAD -> main) Portfolio: birinchi sahifa va README

Har bir commit'ning noyob identifikatori (hash) bor — a3f9c21. HEAD — "siz hozir turgan joy".

#3-qadam: GitHub'ga joylash — push

  1. GitHub'da + → New repository → nom: portfolio → Public → README qo'shmang (bizda bor) → Create repository.
  2. GitHub ko'rsatgan buyruqlarni Git Bash'da bajaring:
Lokal repo'ni GitHub'ga ulash
git remote add origin https://github.com/alivaliyev-dev/portfolio.git
git branch -M main
git push -u origin main      # birinchi marta -u bilan; keyin shunchaki: git push
Parol so'rasaGitHub oddiy parolni qabul qilmaydi. Windows'da odatda brauzer oynasi ochilib, "Sign in with your browser" orqali kirasiz. Agar parol so'ralsa — GitHub'da Settings → Developer settings → Personal access tokens bo'limidan token yaratib, parol o'rniga o'shani kiriting.

GitHub sahifasini yangilang — fayllaringiz va README matni ko'rinadi! 🎉

#4-qadam: branch — xavfsiz tajriba

Saytga qorong'u rejim qo'shmoqchisiz, lekin ishlab turgan versiyani buzishdan qo'rqasiz. Yangi branch oching:

Branch bilan ishlash
git branch                      # branch'lar ro'yxati (* — hozirgisi)
git switch -c dark-mode         # yangi branch yaratib, unga o'tish
# ... style.css'ni o'zgartirasiz, commit qilasiz ...
git add .
git commit -m "Qorong'u rejim qo'shildi"
git switch main                 # main'ga qaytish — o'zgarishlar bu yerda yo'q!
git merge dark-mode             # tayyor bo'lsa — main'ga qo'shish
git push

#6–8-loyihalar: portfolio repository

Topshiriq 6-loyiha: GitHub'da portfolio repository yarating: README.md (o'zingiz, bilimlaringiz, aloqa), index.html (oddiy tanishtiruv sahifasi). 7–8-loyihalar: repo'da kamida 5 ta mazmunli commit bo'lsin (har biri — bitta o'zgarish), bitta branch ochib, uni main'ga birlashtiring. Keyingi mavzulardagi Flowgorithm (.fprg) fayllaringizni ham shu repo'ga flowgorithm/ papkasiga joylab boring. Havolani o'qituvchiga yuboring.

Baholash: README sifati (30%), commit'lar soni va xabarlari (30%), branch + merge (20%), fayllar tartibi (20%).

Bonus: GitHub PagesRepo → Settings → Pages → Branch: main → Save. Bir daqiqadan keyin https://alivaliyev-dev.github.io/portfolio/ manzilida saytingiz butun dunyoga ochiladi!

#Ko'p uchraydigan xatolar

  • ❌ fatal: not a git repository → ✅ Siz repo papkasida emassiz: cd portfolio qiling yoki git init.
  • ❌ nothing to commit → ✅ Faylni saqlamagansiz yoki git add qilmagansiz.
  • ❌ git commit dan keyin qora oyna (Vim) ochilib qoldi → ✅ -m "xabar" ni unutdingiz. Chiqish: Esc, keyin :q! va Enter.
  • ❌ rejected ... fetch first push paytida → ✅ GitHub'da yangi commit bor: avval git pull, keyin git push.
  • ❌ Parol, token, shaxsiy ma'lumotni repo'ga joylash → ✅ Public repo'ni butun dunyo ko'radi! Bunday fayllarni .gitignore ga yozing.

#O'zingizni tekshiring

Git va GitHub farqi?

  1. Ular bir xil narsa
  2. Git — kompyuterdagi dastur, GitHub — repo'larni saqlovchi internet xizmati
  3. GitHub — dastur, Git — sayt
  4. Git faqat rasmlar uchun

Git lokal ishlaydi, GitHub — bulutdagi "uy".

To'g'ri tartib qaysi?

  1. commit → add → push
  2. push → add → commit
  3. add → commit → push
  4. add → push → commit

Konvertga solish → muhr bosish → pochtaga topshirish.

GitHub'dagi repo'ni kompyuterga birinchi marta yuklab olish buyrug'i?

  1. git clone
  2. git init
  3. git push
  4. git log

clone — butun repo va tarixini nusxalaydi; keyingi yangilanishlar — pull.

Asosiy versiyani buzmasdan yangi g'oyani sinash uchun nima ochiladi?

  1. Commit
  2. README
  3. Remote
  4. Branch

Branch — alohida ish yo'nalishi; tayyor bo'lsa merge qilinadi.

git status nima qiladi?

  1. GitHub'ga yuboradi
  2. Fayllar holatini ko'rsatadi: o'zgargan, tayyor, kuzatilmagan
  3. Commit yaratadi
  4. Repo'ni o'chiradi

Eng ko'p ishlatiladigan "nima bo'lyapti?" buyrug'i.
