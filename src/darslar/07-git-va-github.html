Tasavvur qiling: loyihangiz ishlab turibdi, siz yangi funksiya qo'shdingiz va hammasi buzildi. Qaysi o'zgarish sababchi? Kecha ishlagan versiyani qanday qaytarish mumkin? Uch kishi bitta faylni bir vaqtda qanday tahrirlaydi? Git — bu savollarning barchasiga javob beradigan versiyalarni boshqarish tizimi (VCS). Bugun Git'ni bilmaydigan dasturchini ishga olishmaydi. Siz hozir o'qiyotgan qo'llanma ham Git orqali GitHub'ga joylangan.

Git va GitHub — farqi

  • Git — kompyuteringizda ishlaydigan dastur. Loyiha tarixini saqlaydi. Internetsiz ham ishlaydi. 2005-yilda Linus Torvalds (Linux yaratuvchisi) yozgan.
  • GitHub — Git repozitoriyalarini internetda saqlash va jamoa bo'lib ishlash platformasi (Pull Request, Issues, Actions, Pages). Muqobillari: GitLab, Bitbucket.

Git'ning asosiy tushunchalari

Uch hudud

📁 Working Directorysiz tahrirlayotgan fayllar
— git add →
📋 Staging Area (Index)keyingi commit'ga tayyorlanganlar
— git commit →
🗄️ Repository (.git)saqlangan tarix
  • Working directory — oddiy papka va fayllaringiz.
  • Staging area — "savat": qaysi o'zgarishlar keyingi suratga (commit'ga) kirishini tanlaysiz. Bu bir nechta faylni o'zgartirib, ularni mantiqiy jihatdan alohida commit'larga bo'lish imkonini beradi.
  • Repository — .git yashirin papkasi: barcha commit'lar, branch'lar va tarix shu yerda.

Commit

Commit — loyihaning ma'lum paytdagi to'liq surati (snapshot). Har bir commit'da: noyob identifikator (SHA-1 xesh, masalan a3f9c2e), muallif, sana, xabar va ota commit'ga havola bor. Commit'lar zanjiri — loyiha tarixi.

Branch (tarmoq)

Branch — commit'ga ko'rsatkich (yorliq). Yangi branch yaratish — tarixdan "nusxa" olib, asosiy kodga tegmasdan tajriba qilish demak. HEAD — hozir qaysi branch'da turganingizni bildiruvchi maxsus ko'rsatkich.

            C4 ── C5      ← feature/login
           /
C1 ── C2 ── C3 ── C6      ← main  ← HEAD

O'rnatish va sozlash

# Versiyani tekshirish

# Bir martalik sozlash (har bir commit'da ism va email yoziladi)
git config --global user.name "Ismingiz Familiyangiz"
git config --global user.email "siz@example.com"
git config --global init.defaultBranch main
git config --global core.editor "code --wait"     # VS Code muharrir sifatida

Asosiy buyruqlar

# Yangi repozitoriya
git init

# Holat: qaysi fayllar o'zgargan, qaysilari staging'da
git status
git status -s            # qisqa ko'rinish

# O'zgarishlarni ko'rish
git diff                 # working directory vs staging
git diff --staged        # staging vs oxirgi commit

# Staging'ga qo'shish
git add index.html       # bitta fayl
git add src/             # papka
git add .                # barcha o'zgarishlar
git add -p               # o'zgarishlarni bo'lakma-bo'lak tanlash (juda foydali!)

# Commit
git commit -m "Bosh sahifaga navigatsiya qo'shildi"
git commit -am "Xabar"   # kuzatilayotgan fayllarni add + commit (yangi fayllar kirmaydi)

# Tarix
git log
git log --oneline --graph --all     # chiroyli daraxt ko'rinishi
git log -p index.html               # fayl o'zgarishlari tarixi
git show a3f9c2e                    # bitta commit tafsilotlari
git blame app.js                    # har bir qatorni kim, qachon o'zgartirgan

Maxfiy kalitni push qilib qo'ydingizmi? Faylni o'chirib, yangi commit qilish yetarli emas — kalit tarixda qoladi. GitHub'dagi botlar ochiq repozitoriyalardagi kalitlarni bir necha daqiqada topadi. Darhol kalitni bekor qiling (revoke) va yangisini yarating.

Branch'lar bilan ishlash

git branch                       # branch'lar ro'yxati (* — joriy)
git branch feature/cart          # yangi branch yaratish
git switch feature/cart          # unga o'tish (eski usul: git checkout feature/cart)
git switch -c feature/search     # yaratish + o'tish bir buyruqda

# ... o'zgarishlar, commit'lar ...

git switch main                  # asosiy branch'ga qaytish
git merge feature/cart           # feature/cart ni main ga birlashtirish
git branch -d feature/cart       # birlashtirilgan branch'ni o'chirish

Merge turlari

  • Fast-forward — main da yangi commit bo'lmagan bo'lsa, Git shunchaki ko'rsatkichni oldinga suradi. Tarix to'g'ri chiziq.
  • Uch tomonlama merge — ikkala branch'da ham yangi commit'lar bo'lsa, Git yangi merge commit yaratadi.
  • Rebase — git rebase main — sizning commit'laringizni main ning oxiriga "ko'chirib o'tkazadi", tarix chiziqli bo'ladi. Qoida: boshqalar bilan bo'lishilgan (push qilingan) branch'ni rebase qilmang.

Konfliktlar (merge conflict)

Ikki branch bitta faylning bitta qatorini turlicha o'zgartirsa, Git qaysi birini tanlashni bilmaydi va sizdan so'raydi:

<<<<<<< HEAD

Xush kelibsiz, aziz mijoz!

=======

Bizning do'konga xush kelibsiz!

>>>>>>> feature/new-header

Hal qilish tartibi:

  1. Faylni oching; <<<<<<< HEAD va ======= orasida — sizning versiyangiz, ======= va >>>>>>> orasida — birlashtirilayotgan branch versiyasi.
  2. Keraklisini qoldiring (yoki ikkalasini birlashtiring) va barcha belgilarni o'chiring.
  3. git add index.html — "konflikt hal qilindi" deb belgilash.
  4. git commit — merge'ni yakunlash.

VS Code konfliktlarni rangli ko'rsatadi va "Accept Current / Incoming / Both" tugmalarini taklif qiladi. Bekor qilish: git merge --abort.

Xatolarni tuzatish va orqaga qaytish

VaziyatBuyruq
Fayldagi saqlanmagan o'zgarishlarni bekor qilishgit restore app.js
Faylni staging'dan chiqarish (o'zgarish qoladi)git restore --staged app.js
Oxirgi commit xabarini o'zgartirish / unutilgan faylni qo'shish (push qilinmagan bo'lsa)git commit --amend
Oxirgi commit'ni bekor qilish, o'zgarishlarni saqlab qolishgit reset --soft HEAD~1
Push qilingan commit'ni xavfsiz bekor qilish (teskari commit yaratadi)git revert a3f9c2e
Ishni vaqtincha chetga qo'yish (boshqa branch'ga o'tish uchun)git stash → keyin git stash pop
Eski versiyadagi faylni ko'rishgit show a3f9c2e:src/app.js
"Yo'qolgan" commit'ni topishgit reflog
git reset --hard va git push --force — ma'lumotni qaytarib bo'lmas darajada o'chirishi mumkin bo'lgan buyruqlar. Umumiy branch'larda revert dan foydalaning; force push kerak bo'lsa --force-with-lease xavfsizroq.

Remote: GitHub bilan ishlash

# Mavjud repozitoriyani yuklab olish
git clone https://github.com/oybekalloyorov/web_fullstak.git
cd web_fullstak

# Lokal repozitoriyani GitHub'ga ulash
git remote add origin https://github.com/USERNAME/REPO.git
git remote -v                       # ulangan remote'lar

# Yuborish
git push -u origin main             # -u: keyingi safar shunchaki "git push"
git push origin feature/cart        # boshqa branch

# Olish
git fetch origin                    # o'zgarishlarni yuklab olish (birlashtirmasdan)
git pull                            # fetch + merge
git pull --rebase                   # fetch + rebase (tarix toza qoladi)

Autentifikatsiya

GitHub parol bilan push qilishni qabul qilmaydi. Ikki usul bor:

  • HTTPS + Personal Access Token (Settings → Developer settings → Tokens) yoki GitHub CLI: gh auth login.
  • SSH kalit: ssh-keygen -t ed25519 -C "siz@example.com", so'ng ~/.ssh/id_ed25519.pub mazmunini GitHub → Settings → SSH keys ga qo'shing. Remote: git@github.com:USERNAME/REPO.git.

Jamoaviy ish oqimi: GitHub Flow

  1. main — doim ishlaydigan, deploy qilinadigan kod.
  2. Har bir vazifa uchun yangi branch: feature/payment, fix/login-error.
  3. Kichik, mantiqiy commit'lar; muntazam push.
  4. GitHub'da Pull Request (PR) ochish: nima va nima uchun o'zgartirilganini yozish.
  5. Code review: jamoadoshlar kodni ko'rib chiqadi, izoh qoldiradi; avtomatik testlar (CI) ishlaydi.
  6. Tasdiqlangach — main ga merge va branch'ni o'chirish.
  7. Deploy.
Fork va open-source Boshqa birovning loyihasiga hissa qo'shish uchun: repozitoriyani Fork qiling (o'z akkauntingizga nusxa) → clone → branch → o'zgarish → push (o'z fork'ingizga) → asl loyihaga Pull Request oching.

Misol 3

Konfliktni qadamma-qadam hal qilish

Konfliktni o'z kompyuteringizda ataylab yaratib, hal qilishni mashq qilamiz:

mkdir conflict-demo && cd conflict-demo && git init
echo "Narx: 100 000 so'm" > price.txt
git add . && git commit -m "Boshlang'ich narx"

# Birinchi dasturchi: chegirma
git switch -c discount
echo "Narx: 80 000 so'm (chegirma!)" > price.txt
git commit -am "Chegirmali narx"

# Ikkinchi dasturchi (main'da): narx oshdi
git switch main
echo "Narx: 120 000 so'm" > price.txt
git commit -am "Narx oshirildi"

# Birlashtirish
git merge discount
# CONFLICT (content): Merge conflict in price.txt
# Automatic merge failed; fix conflicts and then commit the result.

git status        # both modified: price.txt
cat price.txt

Fayl mazmuni:

<<<<<<< HEAD
Narx: 120 000 so'm
=======
Narx: 80 000 so'm (chegirma!)
>>>>>>> discount

Jamoa bilan kelishib, yangi narxga chegirma qo'llaymiz. Faylni shunday tahrirlaymiz:

Narx: 96 000 so'm (120 000 dan 20% chegirma!)
git add price.txt
git commit -m "Merge discount: yangi narxga chegirma qo'llandi"
git log --oneline --graph
# *   d4e5f6a Merge discount: yangi narxga chegirma qo'llandi
# |\
# | * b2c3d4e Chegirmali narx
# * | c3d4e5f Narx oshirildi
# |/
# * a1b2c3d Boshlang'ich narx
Misol 4

Saytni GitHub Pages'da bepul joylash

Statik sayt (HTML/CSS/JS) uchun eng oson hosting — GitHub Pages. Ushbu qo'llanma ham shu usulda joylanadi.

  1. Repozitoriyaning ildizida index.html bo'lsin va main ga push qiling.
  2. GitHub'da repozitoriya → Settings → Pages.
  3. Source: "Deploy from a branch", Branch: main, papka: / (root) → Save.
  4. 1–2 daqiqadan so'ng sayt https://USERNAME.github.io/REPO/ manzilida ochiladi.

Avtomatlashtirilgan variant — GitHub Actions bilan har push'da deploy:

name: Deploy to GitHub Pages
on:
  push:
    branches: [main]
permissions:
  contents: read
  pages: write
  id-token: write
jobs:
  deploy:
    runs-on: ubuntu-latest
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    steps:
      - uses: actions/checkout@v4
      - uses: actions/configure-pages@v5
      - uses: actions/upload-pages-artifact@v3
        with:
          path: .
      - id: deployment
        uses: actions/deploy-pages@v4

Bunda Settings → Pages → Source sifatida "GitHub Actions" tanlanadi. O'z domeningiz bo'lsa (masalan portfolio.uz), Pages sozlamasida "Custom domain" ga yozing va domen DNS'ida CNAME yozuvini USERNAME.github.io ga yo'naltiring (1-darsdagi DNS bo'limi).

Mashqlar

🏋️ Mustaqil ish

  1. Oldingi darslarda yozgan portfolio va Todo ilovangizni alohida repozitoriyalarga joylang va GitHub Pages orqali e'lon qiling.
  2. Learn Git Branching interaktiv darslarining "Main" bo'limini o'ting.
  3. 3-misoldagi konfliktni takrorlang, lekin bu safar git merge o'rniga git rebase main bilan. Tarixda qanday farq bor?
  4. Do'stingiz bilan bitta repozitoriyada ishlang: har biringiz alohida branch'da bitta faylni o'zgartiring, PR oching, bir-biringizning kodini review qiling.
  5. Ataylab xato commit qiling va uni (a) --amend, (b) reset --soft, (c) revert bilan tuzating. Qaysi biri push'dan keyin xavfsiz?

✅ Xulosa

  • Git — lokal versiyalar tizimi; GitHub — uning ustidagi hamkorlik platformasi.
  • Ish sikli: o'zgartirish → git add → git commit → git push.
