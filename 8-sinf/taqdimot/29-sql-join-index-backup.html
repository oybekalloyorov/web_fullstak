Nima uchun JOIN kerak?

  • Ma'lumotlarni takrorlamaslik uchun ajratdik: o'quvchilar, sinflar, baholar alohida
  • Savol: "Ali qaysi sinfda va sinf rahbari kim?" → ikkala jadval kerak
💡
Ikki ro'yxat: birinchisida "O'quvchi — sinf raqami", ikkinchisida "Sinf raqami — rahbar". Ali'ning raqamini topib, ikkinchi ro'yxatdan qidirasiz. JOIN buni millionlab qator uchun bir zumda qiladi.

INNER JOIN

SQL
SELECT o.ism, o.familiya, s.nomi AS sinf, s.sinf_rahbari
FROM oquvchilar AS o
JOIN sinflar AS s ON o.sinf_id = s.id      -- JOIN = INNER JOIN
ORDER BY s.nomi, o.familiya;
Natija
 ism     | familiya  | sinf | sinf_rahbari
---------+-----------+------+-----------------

 Ali     | Valiyev   | 8-A  | Karimova Nodira
 Bobur   | Toshmatov | 8-B  | Rasulov Akmal
  • ON o.sinf_id = s.id — qaysi ustunlar bo'yicha moslash (odatda FK = PK)
  • o, s — taxalluslar; bir xil nomli ustunlarni (id) aniq ko'rsatadi

JOIN turlari

TurNatija
INNER JOINFaqat ikkala jadvalda mos keladiganlar (kesishma)
LEFT JOINChap jadvalning hammasi + o'ngdan moslar (yo'q bo'lsa NULL)
RIGHT JOINO'ng jadvalning hammasi + chapdan moslar
FULL JOINIkkala jadvalning hammasi
SQL
SELECT o.ism, s.nomi FROM oquvchilar o LEFT JOIN sinflar s ON o.sinf_id = s.id;
-- "Yangi Keldi" ham chiqadi, sinfi — NULL
"Mos kelmaganlar ko'rinishi kerakmi?" Yo'q → INNER. Chapning hammasi → LEFT

LEFT JOIN bilan "yo'q"larni topish

SQL
-- Hali birorta ham baho olmagan o'quvchilar
SELECT o.ism, o.familiya
FROM oquvchilar o
LEFT JOIN baholar b ON b.oquvchi_id = o.id
WHERE b.id IS NULL;
  • Bahosi yo'q o'quvchida b ustunlari NULL bo'ladi
  • Amalda RIGHT JOIN kam ishlatiladi — jadvallar o'rnini almashtirib LEFT yoziladi

Uch jadvalni va N:M ni birlashtirish

SQL
SELECT o.ism || ' ' || o.familiya AS oquvchi, s.nomi AS sinf, b.fan, b.baho
FROM baholar b
JOIN oquvchilar o ON b.oquvchi_id = o.id
JOIN sinflar s    ON o.sinf_id = s.id
WHERE b.fan = 'Matematika'
ORDER BY b.baho DESC;

-- Ko'pga-ko'p: oraliq jadval orqali
SELECT o.ism, t.nomi AS togarak
FROM oquvchilar o
JOIN azoliklar a  ON a.oquvchi_id = o.id
JOIN togaraklar t ON t.id = a.togarak_id;

Indekslar — qidiruvni tezlashtirish

💡
Kitob ko'rsatkichi: "Fotosintez"ni topish uchun 300 betni varaqlamaysiz — oxiridagi ko'rsatkichga qaraysiz: "47, 112-betlar". Indeks — baza uchun shunday ko'rsatkich.
SQL
CREATE INDEX idx_oquvchilar_familiya ON oquvchilar (familiya);
CREATE INDEX idx_baholar_oquvchi ON baholar (oquvchi_id);   -- FK uchun foydali
EXPLAIN SELECT * FROM oquvchilar WHERE familiya = 'Karimova';
DROP INDEX idx_oquvchilar_familiya;
  • PRIMARY KEY va UNIQUE ga indeks avtomatik
  • O'qishni tezlashtiradi, yozishni biroz sekinlashtiradi — faqat tez-tez qidiriladigan ustunlarga

Backup va Restore

"Tekshirilmagan zaxira — zaxira emas" — tiklashni ham sinab ko'ring
  • pgAdmin: baza → o'ng tugma → Backup... (Custom) / yangi baza → Restore...
Terminal
pg_dump -U postgres -d maktab -f maktab_backup.sql       # SQL fayl
pg_dump -U postgres -d maktab -F c -f maktab.backup      # siqilgan

createdb -U postgres maktab_yangi
psql -U postgres -d maktab_yangi -f maktab_backup.sql     # tiklash
pg_restore -U postgres -d maktab_yangi maktab.backup
  • .sql faylni oching — u CREATE TABLE va INSERT lardan iborat!

19-loyiha: mahsulotlar va buyurtmalar bazasi

Amaliyot: jadvallar

SQL
CREATE TABLE mijozlar (
    id SERIAL PRIMARY KEY, ism VARCHAR(100) NOT NULL, telefon VARCHAR(20) UNIQUE
);
CREATE TABLE mahsulotlar (
    id SERIAL PRIMARY KEY, nomi VARCHAR(100) NOT NULL,
    narx NUMERIC(12, 2) NOT NULL CHECK (narx > 0),
    soni INTEGER NOT NULL DEFAULT 0 CHECK (soni >= 0)
);
CREATE TABLE buyurtmalar (
    id SERIAL PRIMARY KEY,
    mijoz_id INTEGER NOT NULL REFERENCES mijozlar(id),
    sana TIMESTAMP DEFAULT NOW(),
    holat VARCHAR(20) DEFAULT 'yangi'
);
CREATE TABLE buyurtma_tarkibi (
    buyurtma_id INTEGER REFERENCES buyurtmalar(id) ON DELETE CASCADE,
    mahsulot_id INTEGER REFERENCES mahsulotlar(id),
    soni INTEGER NOT NULL CHECK (soni > 0),
    narx NUMERIC(12, 2) NOT NULL,
    PRIMARY KEY (buyurtma_id, mahsulot_id)
);

Amaliyot: so'rovlar

SQL
-- 1. Buyurtma, mijoz, sana, holat
SELECT b.id, m.ism, b.sana, b.holat
FROM buyurtmalar b JOIN mijozlar m ON m.id = b.mijoz_id;

-- 2. 1-buyurtma tarkibi va summasi
SELECT p.nomi, t.soni, t.narx, t.soni * t.narx AS summa
FROM buyurtma_tarkibi t JOIN mahsulotlar p ON p.id = t.mahsulot_id
WHERE t.buyurtma_id = 1;

-- 3. Buyurtma bermagan mijozlar
SELECT m.ism FROM mijozlar m
LEFT JOIN buyurtmalar b ON b.mijoz_id = m.id
WHERE b.id IS NULL;

Ko'p uchraydigan xatolar

  • ❌ column reference "id" is ambiguous — o.id yoki s.id deb aniq yozing

  • ❌ LEFT JOIN dan keyin o'ng jadval bo'yicha WHERE — INNER'ga aylanib qoladi
  • ❌ Zaxirani o'sha kompyuterda saqlash
