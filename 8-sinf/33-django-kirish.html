Django frameworkiga kirish. Arxitektura, loyiha va ilova (App) yaratish

Framework nima va nima uchun Django, MVT arxitekturasi, so'rovning Django ichidagi yo'li, o'rnatish, startproject va startapp, loyiha fayllari, settings.py, runserver, PostgreSQL'ga ulash.

🎯 Bu darsda nimani o'rganasiz

  • Framework nima va Django nima uchun shunchalik mashhurligini;
  • Django'ning MVT (Model–View–Template) arxitekturasini;
  • Foydalanuvchi so'rovi Django ichida qanday yo'l bosib o'tishini;
  • Django'ni o'rnatish, loyiha va ilova (app) yaratishni;
  • Loyihani PostgreSQL bazasiga ulashni.

Shu darsdan boshlab 38-mavzugacha bitta haqiqiy loyiha — "Maktab blogi"ni bosqichma-bosqich quramiz.

#Framework nima?

32-mavzuda Python va baza bilan konsol dastur yozdik. Endi uni veb-saytga aylantirish uchun ko'p narsa kerak: brauzer so'rovlarini qabul qilish, manzillarni (URL) tahlil qilish, HTML sahifalar yasash, formalarni tekshirish, foydalanuvchilarni ro'yxatdan o'tkazish, parollarni xavfsiz saqlash, admin panel... Bularning hammasini noldan yozish — oylar.

Framework — tayyor "karkas": dasturchilar tomonidan ko'p yillar davomida sinalgan, keng tarqalgan vazifalarni allaqachon hal qilgan kod to'plami. Siz faqat o'z loyihangizga xos qismlarni yozasiz.

O'xshatish: uy qurish Noldan dastur yozish — g'ishtni o'zingiz pishirib, uy qurish. Framework bilan ishlash — tayyor karkas (poydevor, devorlar, elektr va suv quvurlari) ustida xonalarni o'zingizga moslab bezash. Tezroq, xavfsizroq va sifatliroq.

#Nima uchun Django?

  • 🔋 "Batareyalar bilan birga" — admin panel, foydalanuvchilar tizimi, formalar, ORM, xavfsizlik — hammasi tayyor.
  • 🔐 Xavfsiz — SQL injection, XSS, CSRF kabi hujumlardan avtomatik himoya.
  • 📈 Masshtablanadi — Instagram, Pinterest, Spotify, Mozilla saytlari Django'da ishlaydi (yoki ishlagan).
  • 📚 Ajoyib hujjatlar va katta jamiyat. Shiori: "Muddati bor perfeksionistlar uchun veb-framework".

#Loyiha (project) va ilova (app)

  • Loyiha (project) — butun veb-sayt: umumiy sozlamalar, asosiy URL'lar. Bitta.
  • Ilova (app) — saytning mustaqil qismi, bitta vazifaga mas'ul: blog, accounts (foydalanuvchilar), shop. Loyihada bir nechta bo'ladi va ularni boshqa loyihalarda qayta ishlatish mumkin.
O'xshatish: maktab binosi Loyiha — maktab binosi (umumiy qoidalar, kirish eshigi, qo'ng'iroq). Ilovalar — binodagi xonalar: kutubxona, sport zali, oshxona. Har biri o'z ishini qiladi, lekin hammasi bitta binoda va umumiy qoidalarga bo'ysunadi.

#O'rnatish va loyiha yaratish

  1. Loyiha papkasi va virtual muhit:
    Terminal
    mkdir maktab_blog
cd maktab_blog
python -m venv venv
venv\Scripts\activate              # Windows  (macOS/Linux: source venv/bin/activate)

pip install django "psycopg[binary]" python-dotenv
python -m django --version          # 5.x
  2. Loyiha yaratish (oxiridagi nuqtaga e'tibor bering — joriy papkada yaratadi):
    Terminal
    django-admin startproject config .
  3. Serverni ishga tushirish:
    Terminal
    python manage.py runserver
    Natija
    Watching for file changes with StatReloader

Quit the server with CTRL-BREAK.
    Brauzerda http://127.0.0.1:8000 ni oching — raketa 🚀 va "The install worked successfully!" yozuvi. Tabriklaymiz!
  4. Ilova yaratish:
    Terminal
    python manage.py startapp blog
  5. Ilovani loyihaga ro'yxatdan o'tkazish — config/settings.py da:
    config/settings.py
    INSTALLED_APPS = [
    "django.contrib.admin",
    "django.contrib.auth",
    "django.contrib.contenttypes",
    "django.contrib.sessions",
    "django.contrib.messages",

runserver — faqat ishlab chiqish (development) uchun server. Kod o'zgarganda avtomatik qayta ishga tushadi. Internetga chiqarish uchun boshqa server ishlatiladi (41-mavzu). Serverni to'xtatish: Ctrl+C.

#settings.py — asosiy sozlamalar

config/settings.py (muhim qismlari)
from pathlib import Path
import os
from dotenv import load_dotenv

BASE_DIR = Path(__file__).resolve().parent.parent      # loyiha papkasi
load_dotenv(BASE_DIR / ".env")

SECRET_KEY = os.getenv("SECRET_KEY", "dev-uchun-vaqtinchalik-kalit")   # MAXFIY!
DEBUG = os.getenv("DEBUG", "True") == "True"           # ishlab chiqishda True, serverda False
ALLOWED_HOSTS = os.getenv("ALLOWED_HOSTS", "127.0.0.1,localhost").split(",")

LANGUAGE_CODE = "uz"                                    # admin panel o'zbek tilida
TIME_ZONE = "Asia/Tashkent"
USE_I18N = True
USE_TZ = True
SECRET_KEY va DEBUG SECRET_KEY — loyihaning maxfiy kaliti (parollar, sessiyalar xavfsizligi uchun). Uni GitHub'ga yuklamang — .env da saqlang. DEBUG = True xato bo'lganda batafsil ma'lumot ko'rsatadi — o'rganish uchun ajoyib, lekin internetdagi saytda har doim False bo'lishi shart.

#PostgreSQL'ga ulash

Django standart holatda SQLite (bitta fayldagi oddiy baza) ishlatadi. Biz PostgreSQL'ga ulaymiz:

  1. pgAdmin'da yangi baza yarating: maktab_blog.
  2. Loyiha papkasida .env fayl:
    .env
    SECRET_KEY=bu-yerga-uzun-tasodifiy-satr-yozing
DEBUG=True
DB_NAME=maktab_blog
DB_USER=postgres
DB_PASSWORD=SIZNING_PAROLINGIZ
DB_HOST=localhost
DB_PORT=5432
  3. settings.py dagi DATABASES ni almashtiring:
    config/settings.py
    DATABASES = {
    "default": {
        "ENGINE": "django.db.backends.postgresql",
        "NAME": os.getenv("DB_NAME"),
        "USER": os.getenv("DB_USER"),
        "PASSWORD": os.getenv("DB_PASSWORD"),
        "HOST": os.getenv("DB_HOST", "localhost"),
        "PORT": os.getenv("DB_PORT", "5432"),
    }
}
  4. Django'ning o'z jadvallarini (foydalanuvchilar, sessiyalar...) yarating:
    Terminal
    python manage.py migrate
    Natija
    Operations to perform:
  Apply all migrations: admin, auth, contenttypes, sessions
Running migrations:
  Applying contenttypes.0001_initial... OK
  Applying auth.0001_initial... OK
  ...
    pgAdmin'da maktab_blog bazasini yangilang — auth_user, django_session kabi jadvallar paydo bo'ldi! Ularni Django o'zi yaratdi.
  5. .gitignore fayl:
    .gitignore
    venv/
.env
__pycache__/
*.pyc
db.sqlite3

#Birinchi sahifa (oldindan ko'rish)

Keyingi mavzuda batafsil o'rganamiz, lekin hoziroq natija ko'raylik:

blog/views.py
from django.http import HttpResponse

def bosh_sahifa(request):
    return HttpResponse("<h1>Maktab blogiga xush kelibsiz! 🎉</h1>")
config/urls.py
from django.contrib import admin
from django.urls import path
from blog import views

urlpatterns = [
    path("admin/", admin.site.urls),
    path("", views.bosh_sahifa),          # "" — bosh sahifa (http://127.0.0.1:8000/)
]

Serverni ishga tushiring va bosh sahifani yangilang — raketa o'rnida sizning xabaringiz!

#Amaliy mashg'ulot

  1. Yuqoridagi barcha qadamlarni bajaring: venv → Django → config loyihasi → blog ilovasi → PostgreSQL → migrate → birinchi sahifa.
  2. pip freeze > requirements.txt bilan paketlar ro'yxatini saqlang.
  3. Loyihani Git repozitoriyasiga aylantiring va GitHub'ga push qiling (.env va venv yuklanmaganiga ishonch hosil qiling!).
  4. Tajriba: views.py da ataylab xato qiling (masalan, HttpRespons) va sahifani yangilang. Django'ning sariq xato sahifasini o'qing — u qaysi faylning qaysi qatorida xato borligini ko'rsatadi (bu DEBUG=True tufayli). Xatoni tuzating.
  5. python manage.py ni argumentsiz ishga tushiring va mavjud buyruqlar ro'yxatini ko'ring.

#Ko'p uchraydigan xatolar

  • ❌ ModuleNotFoundError: No module named 'django' — virtual muhit faollashtirilmagan (terminal boshida (venv) yo'q).
  • ❌ startproject config (nuqtasiz) — ortiqcha ichma-ich papka yaratiladi: config/config/.
  • ❌ Ilovani INSTALLED_APPS ga qo'shishni unutish — modellar va shablonlar topilmaydi.
  • ❌ Error: That port is already in use — server allaqachon boshqa terminalda ishlayapti. Uni to'xtating yoki runserver 8001.
  • ❌ password authentication failed — .env dagi parol noto'g'ri yoki load_dotenv chaqirilmagan.
