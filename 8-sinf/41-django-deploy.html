41-mavzu · 42 tadan · V bob. DRF va deploy

Django loyihasini serverga joylash (Deploy)

Deploy nima, development va production farqi, hosting turlari; loyihani tayyorlash: DEBUG, SECRET_KEY, ALLOWED_HOSTS, gunicorn, whitenoise, dj-database-url, requirements.txt, collectstatic; Render'ga bosqichma-bosqich joylash, PostgreSQL, superuser; PythonAnywhere muqobili; deploy'dan keyingi tekshiruv.

2 soat · amaliy

🎯 Bu darsda nimani o'rganasiz

  • Deploy nima va "mening kompyuterimda ishlaydi" dan "internetda ishlaydi" ga qanday o'tishni;
  • Development va production muhitlari farqini;
  • Django loyihasini serverga tayyorlashni (xavfsizlik sozlamalari, statik fayllar, server dasturi);
  • Loyihani Render bulutli platformasiga PostgreSQL bilan bosqichma-bosqich joylashni (30-loyiha);
  • Joylangan saytni tekshirish va yangilashni.

#Deploy nima?

Hozirgacha blogimiz faqat sizning kompyuteringizda, 127.0.0.1:8000 da ishladi — uni hech kim ko'ra olmaydi. Deploy (joylash) — dasturni foydalanuvchilar ishlatishi uchun internetga ulangan serverga o'rnatish va ishga tushirish.

O'xshatish: oshxona va restoran Uyda ovqat pishirish (development) — o'zingiz uchun, xato qilsangiz ham hech kim bilmaydi. Restoran ochish (production) — boshqa narsa: sanitariya qoidalari (xavfsizlik), katta oshxona (server), doimiy ish vaqti (24/7), ko'p mijozlarga bir vaqtda xizmat. Retsept bir xil, lekin talablar butunlay boshqa.

settings.py — muhitga qarab sozlash

config/settings.py
import os
from pathlib import Path
import dj_database_url
from dotenv import load_dotenv

BASE_DIR = Path(__file__).resolve().parent.parent
load_dotenv(BASE_DIR / ".env")                 # lokal kompyuterda .env, serverda — muhit o'zgaruvchilari

# 🔐 Xavfsizlik
SECRET_KEY = os.environ["SECRET_KEY"]          # o'rnatilmagan bo'lsa — xato (ataylab!)
DEBUG = os.getenv("DEBUG", "False") == "True"  # standart — False
ALLOWED_HOSTS = os.getenv("ALLOWED_HOSTS", "127.0.0.1,localhost").split(",")
CSRF_TRUSTED_ORIGINS = [f"https://{h}" for h in ALLOWED_HOSTS if h not in ("127.0.0.1", "localhost")]

MIDDLEWARE = [
    "corsheaders.middleware.CorsMiddleware",
    "django.middleware.security.SecurityMiddleware",
    "whitenoise.middleware.WhiteNoiseMiddleware",       # ⬅ SecurityMiddleware'dan keyin
    "django.contrib.sessions.middleware.SessionMiddleware",
    # ... qolganlari o'zgarishsiz
]

# 🐘 Baza: serverda DATABASE_URL, lokal kompyuterda .env'dagi qiymatlar
DATABASES = {
    "default": dj_database_url.config(
        default=f"postgres://{os.getenv('DB_USER')}:{os.getenv('DB_PASSWORD')}@"
                f"{os.getenv('DB_HOST', 'localhost')}:{os.getenv('DB_PORT', '5432')}/{os.getenv('DB_NAME')}",
        conn_max_age=600,
    )
}

# 📁 Statik fayllar
STATIC_URL = "static/"
STATIC_ROOT = BASE_DIR / "staticfiles"                  # collectstatic shu yerga yig'adi
STORAGES = {
    "default": {"BACKEND": "django.core.files.storage.FileSystemStorage"},
    "staticfiles": {"BACKEND": "whitenoise.storage.CompressedManifestStaticFilesStorage"},
}

# 🔒 Production'da qo'shimcha himoya
if not DEBUG:
    SECURE_PROXY_SSL_HEADER = ("HTTP_X_FORWARDED_PROTO", "https")
    SESSION_COOKIE_SECURE = True
    CSRF_COOKIE_SECURE = True
Production'ning oltin qoidalari
  1. DEBUG = False — aks holda xato sahifasi buzg'unchiga kodingiz, sozlamalar va hatto parollar haqida ma'lumot beradi.
  2. SECRET_KEY maxfiy va yangi — GitHub'dagi yoki darsdagi kalitni ishlatmang. Yangisini yarating: python -c "from django.core.management.utils import get_random_secret_key; print(get_random_secret_key())"
  3. ALLOWED_HOSTS — faqat sizning domeningiz.

Lokal kompyuteringizdagi .env ga DEBUG=True qo'shib qo'ying — shunda kompyuteringizda ishlash qulay qoladi.

#2-bosqich: Render'ga joylash

  1. render.com da GitHub akkauntingiz bilan ro'yxatdan o'ting.
  2. PostgreSQL bazasi yarating: Dashboard → New + → Postgres → nom (maktab-blog-db), region (Frankfurt — O'zbekistonga yaqinroq), bepul tarif → Create Database. Tayyor bo'lgach, Internal Database URL ni nusxalang (postgresql://...).
  3. Web Service yarating: New + → Web Service → GitHub repozitoriyangizni tanlang.

Xatolarni topish

  • Logs — barcha xatolar shu yerda. "Build failed" bo'lsa — build log'ini, sayt 500 qaytarsa — runtime log'ini o'qing.
  • DisallowedHost → ALLOWED_HOSTS da domen yo'q yoki xato yozilgan.
  • CSS yo'q (oddiy matn ko'rinishidagi sayt) → WhiteNoise middleware yoki collectstatic muammosi.
  • CSRF verification failed (forma yuborishda) → CSRF_TRUSTED_ORIGINS da https:// bilan domen yo'q.
  • ModuleNotFoundError → paket requirements.txt ga yozilmagan (pip freeze > requirements.txt ni unutgansiz).
  • Hech qachon muammoni "tuzatish" uchun serverda DEBUG=True qo'ymang!
Media fayllar haqida Bulutli platformalarning disk xotirasi ko'pincha vaqtinchalik: har deploy'da foydalanuvchilar yuklagan rasmlar o'chib ketishi mumkin. Haqiqiy loyihalarda media fayllar alohida xizmatda (Cloudinary, Amazon S3) saqlanadi. O'quv loyihasi uchun bu muammo emas, lekin buni bilib qo'ying.

#Muqobil: PythonAnywhere (qisqacha)

  1. pythonanywhere.com da bepul "Beginner" akkaunt oching.
  2. Consoles → Bash: git clone https://github.com/USERNAME/maktab_blog.git, virtual muhit yarating va pip install -r requirements.txt.
  3. Web → Add a new web app → Manual configuration → Python versiyasi. WSGI fayliga loyiha yo'li va DJANGO_SETTINGS_MODULE = "config.settings" ni yozing.
  4. Bepul tarifda PostgreSQL yo'q — DATABASE_URL o'rniga SQLite (sqlite:///db.sqlite3) ishlatiladi. Static fayllar uchun Web sahifasida /static/ → staticfiles papkasini ko'rsating.
  5. Reload — sayt USERNAME.pythonanywhere.com da.

#O'zingizni tekshiring

Production serverda DEBUG qanday bo'lishi kerak va nima uchun?

  1. True — xatolarni ko'rish uchun
  2. False — xato sahifalari maxfiy ma'lumotlarni oshkor qilmasligi uchun
  3. Ahamiyati yo'q
  4. None

Production'da runserver o'rniga ishlatiladigan server dasturi?

  1. whitenoise
  2. pip
  3. psql
  4. gunicorn

Barcha statik fayllarni bitta papkaga yig'uvchi buyruq?

  1. python manage.py collectstatic
  2. python manage.py migrate
  3. python manage.py static
  4. pip install static

Saytingiz DisallowedHost xatosini berdi. Sababi?

  1. Baza ulanmagan
  2. CSS topilmadi
  3. Domen ALLOWED_HOSTS da yo'q
  4. Parol noto'g'ri

Maxfiy kalitlar (SECRET_KEY, baza paroli) production'da qayerda saqlanadi?

  1. settings.py ichida
  2. Hosting'ning muhit o'zgaruvchilarida (environment variables)
  3. GitHub README'da
  4. HTML shablonda
