#API nima?

IV bobda Django HTML sahifalar qaytardi — ularni faqat brauzer ko'rsata oladi. Lekin bugun bitta xizmatdan ko'plab "mijozlar" foydalanadi:

  • 📱 Mobil ilova (Android, iOS) — unga HTML kerak emas, faqat ma'lumot kerak;
  • ⚛️ React/Vue kabi frontend dasturlar — sahifani o'zi chizadi, serverdan faqat ma'lumot oladi;
  • 🤖 Telegram bot, boshqa saytlar, aqlli soatlar...

API (Application Programming Interface — dasturlash interfeysi) — dasturlar bir-biri bilan "gaplashishi" uchun kelishilgan qoidalar. Veb-API — ma'lumotni JSON ko'rinishida beradigan URL'lar to'plami.

O'xshatish: restoran (yana!) va yetkazib berish IV bobdagi sayt — restoran zali: taom chiroyli likopchada (HTML) beriladi. API — yetkazib berish xizmati: o'sha oshxona, o'sha taom, lekin konteynerda (JSON). Mijoz uni o'z uyida (mobil ilova, React sayt) o'zi xohlagan likopchaga soladi. Oshxona (back-end) bitta — mijozlar ko'p.

#JSON — ma'lumot almashish tili

24-mavzuda tanishgan JSON (JavaScript Object Notation) — API'larning asosiy formati. U Python'dagi dict/list'ga va JavaScript'dagi obyekt/massivga juda o'xshaydi:

JSON
{
  "id": 5,
  "sarlavha": "Bilimlar bellashuvi",
  "chop_etilgan": true,
  "korishlar": 128,
  "kategoriya": { "id": 2, "nomi": "Tadbirlar" },
  "teglar": ["olimpiada", "8-sinf"],
  "rasm": null
}

Qoidalar: kalitlar qo'sh qo'shtirnoqda; qiymatlar — matn, son, true/false, null, obyekt {} yoki massiv [].

#REST arxitekturasi

REST — API'ni tartibli va tushunarli loyihalash uslubi. Asosiy g'oya: hamma narsa — resurs (maqola, foydalanuvchi, mahsulot), har bir resursning o'z URLi bor, amallar esa HTTP metodlari bilan bildiriladi.

Amal (CRUD)HTTP metodURLJavob kodi
Barcha maqolalar ro'yxatiGET/api/maqolalar/200 OK
Bitta maqolaGET/api/maqolalar/5/200 / 404
Yangi maqola yaratishPOST/api/maqolalar/201 Created
To'liq yangilashPUT/api/maqolalar/5/200
Qisman yangilashPATCH/api/maqolalar/5/200
O'chirishDELETE/api/maqolalar/5/204 No Content
  • URL'da ot (resurs), ko'plikda: /api/maqolalar/ ✅, /api/getMaqola/ ❌, /api/maqola/ochir/5/ ❌ — amal metod orqali bildiriladi.
  • Xatolar ham status kod bilan: 400 — noto'g'ri ma'lumot, 401 — tizimga kirilmagan, 403 — ruxsat yo'q, 404 — topilmadi.

#Serializer — tarjimon

Bazadan olingan Maqola obyektini to'g'ridan-to'g'ri JSON qilib bo'lmaydi. Serializer ikki yo'nalishda ishlaydi:

  • Serializatsiya: model obyekti → Python dict → JSON (javob yuborish uchun);
  • Deserializatsiya: JSON → tekshirish (validatsiya) → model obyekti (kelgan ma'lumotni saqlash uchun).
Django Forms bilan o'xshashlik Serializer — API uchun Forma (37-mavzu): u ham maydonlarni belgilaydi, ma'lumotni tekshiradi va saqlaydi. Farqi: forma HTML bilan, serializer JSON bilan ishlaydi. Form ↔ Serializer, ModelForm ↔ ModelSerializer.
blog/serializers.py (yangi fayl)
from rest_framework import serializers
from .models import Kategoriya, Maqola


class KategoriyaSerializer(serializers.ModelSerializer):
    class Meta:
        model = Kategoriya
        fields = ["id", "nomi", "slug"]


class MaqolaSerializer(serializers.ModelSerializer):
    muallif = serializers.ReadOnlyField(source="muallif.username")        # faqat o'qish uchun
    kategoriya_nomi = serializers.ReadOnlyField(source="kategoriya.nomi")

    class Meta:
        model = Maqola
        fields = ["id", "sarlavha", "matn", "kategoriya", "kategoriya_nomi",
                  "muallif", "chop_etilgan", "korishlar", "yaratilgan"]
        read_only_fields = ["korishlar", "yaratilgan"]

    def validate_sarlavha(self, qiymat):                # Forms'dagi clean_sarlavha kabi
        if len(qiymat.strip()) < 5:
            raise serializers.ValidationError("Sarlavha kamida 5 belgi bo'lsin")
        return qiymat.strip()

#API View'lar

1-usul: @api_view — funksiya asosida

blog/api_views.py (yangi fayl)
from django.shortcuts import get_object_or_404
from rest_framework import status
from rest_framework.decorators import api_view
from rest_framework.response import Response

from .models import Maqola
from .serializers import MaqolaSerializer


@api_view(["GET", "POST"])
def maqolalar_api(request):
    if request.method == "GET":
        maqolalar = Maqola.objects.filter(chop_etilgan=True)
        serializer = MaqolaSerializer(maqolalar, many=True)
        return Response(serializer.data)                             # 200 + JSON

    # POST — yangi maqola
    serializer = MaqolaSerializer(data=request.data)                 # request.data — kelgan JSON
    if serializer.is_valid():
        serializer.save(muallif=request.user)                        # muallifni o'zimiz beramiz
        return Response(serializer.data, status=status.HTTP_201_CREATED)
    return Response(serializer.errors, status=status.HTTP_400_BAD_REQUEST)


@api_view(["GET"])
def maqola_api(request, id):
    maqola = get_object_or_404(Maqola, id=id, chop_etilgan=True)
    return Response(MaqolaSerializer(maqola).data)

2-usul: APIView — klass asosida

Python
from rest_framework.views import APIView

class MaqolalarAPI(APIView):
    def get(self, request):
        serializer = MaqolaSerializer(Maqola.objects.filter(chop_etilgan=True), many=True)
        return Response(serializer.data)

    def post(self, request):
        serializer = MaqolaSerializer(data=request.data)
        serializer.is_valid(raise_exception=True)        # xato bo'lsa — avtomatik 400
        serializer.save(muallif=request.user)
        return Response(serializer.data, status=status.HTTP_201_CREATED)
blog/urls.py
from . import api_views

urlpatterns += [
    path("api/maqolalar/", api_views.maqolalar_api, name="api_maqolalar"),
    path("api/maqolalar/<int:id>/", api_views.maqola_api, name="api_maqola"),
]

#Brauzerda ko'rinadigan API

#Amaliy mashg'ulot

  1. DRF'ni o'rnating va sozlang.
  2. serializers.py yarating, shell'da serializatsiya va validatsiyani sinab ko'ring.
  3. @api_view bilan ikkita endpoint yarating va brauzerda oching.
  4. Admin orqali tizimga kiring, so'ng brauzerdagi API sahifasida POST forma orqali yangi maqola yarating (JSON):
    JSON
    {
  "sarlavha": "API orqali yaratilgan maqola",
  "matn": "Bu maqola DRF yordamida qo'shildi!",
  "kategoriya": 1
}
    Javob kodi 201 ekanini tekshiring. Sarlavhani 3 belgili qilib yuboring — 400 va xato xabari.
  5. /api/kategoriyalar/ endpointini yarating (KategoriyaSerializer), har bir kategoriyada maqolalar soni ham bo'lsin (Maslahat: serializers.IntegerField(source="maqolalar.count", read_only=True)).

#Ko'p uchraydigan xatolar

  • ❌ Object of type Maqola is not JSON serializable — obyekt serializer'dan o'tkazilmagan.
  • ❌ Ro'yxat uchun many=True unutilgan — AttributeError.
  • ❌ serializer.data ni is_valid() dan oldin o'qish (data= bilan yaratilganda).
  • ❌ "rest_framework" INSTALLED_APPS ga qo'shilmagan — brauzerdagi API sahifasi shablon xatosi beradi.
  • ❌ POST so'rov 403 qaytaradi — tizimga kirilmagan (IsAuthenticatedOrReadOnly).
