Autentifikatsiya va avtorizatsiya

Uning ortida esa veb-xavfsizlikning eng nozik qismi yotadi: parollarni qanday saqlash, foydalanuvchini keyingi so'rovlarda qanday "tanish", kimga nimaga ruxsat berish. #Parollarni saqlash: xeshlash

Qoida №1: parolni hech qachon ochiq holda saqlamang. Baza o'g'irlansa (bu katta kompaniyalarda ham bo'ladi), barcha parollar oshkor bo'ladi — odamlar esa bir xil parolni ko'p saytda ishlatadi.

Nima uchun shifrlash emas, xeshlash?

  • Shifrlash — ikki tomonlama: kalit bilan qayta ochish mumkin. Kalit o'g'irlansa — hamma parollar ochiladi.
  • Xeshlash — bir tomonlama funksiya: hash("salom123") → "$2b$12$Kix...", lekin xeshdan parolni qaytarib bo'lmaydi. Tekshirishda kiritilgan parol qayta xeshlanadi va solishtiriladi.

Nima uchun MD5/SHA-256 emas?

Ular tez ishlash uchun yaratilgan — zamonaviy GPU sekundiga milliardlab SHA-256 hisoblaydi va oddiy parollarni lug'at hujumi bilan bir zumda topadi. Parollar uchun ataylab sekin va tuzli (salted) algoritmlar kerak:

  • bcrypt — eng ko'p ishlatiladigan; "cost factor" (masalan 12) bilan sekinlik sozlanadi.
  • argon2id — zamonaviy tavsiya (OWASP), xotirani ham talab qiladi.
  • Tuz (salt) — har bir parolga qo'shiladigan tasodifiy qiymat. Bir xil parollar har xil xeshga ega bo'ladi, tayyor "rainbow table"lar ishlamaydi. bcrypt tuzni avtomatik yaratadi va xesh ichida saqlaydi.
JavaScript
import bcrypt from 'bcrypt';      // npm install bcrypt   (yoki sof JS: bcryptjs)

const hash = await bcrypt.hash('MeningParolim2026', 12);
// '$2b$12$C6UzMDM.H6dfI/f/IKcEeO5H8v.Lk3PqxW7JLw7xYcR9EJzt4P6eW'
//  │   │  └─ 22 belgili tuz + 31 belgili xesh
//  │   └─ cost = 12 (2^12 = 4096 iteratsiya)
//  └─ algoritm versiyasi

const ok = await bcrypt.compare('MeningParolim2026', hash);   // true
const bad = await bcrypt.compare('boshqa', hash);              // false

#Foydalanuvchini "eslab qolish": sessiya va token

HTTP holatsiz (1-dars) — server har bir so'rovda kim kelganini bilmaydi. Login'dan keyin mijozga "guvohnoma" beriladi va u har bir so'rov bilan uni ko'rsatadi. Ikki asosiy yondashuv bor:

1. Sessiyalar (stateful)

  1. Login muvaffaqiyatli → server tasodifiy sessiya ID yaratadi va uni serverda (Redis yoki bazada) saqlaydi: sid_abc → { userId: 7 }.
  2. ID mijozga Set-Cookie: sid=abc; HttpOnly; Secure orqali yuboriladi.
  3. Brauzer har so'rovda cookie'ni avtomatik yuboradi; server ID bo'yicha foydalanuvchini topadi.
  4. Chiqish — serverdagi yozuvni o'chirish. Darhol, ishonchli.

2. JWT tokenlar (stateless)

JWT (JSON Web Token) — server imzolagan va ichida ma'lumot saqlovchi satr. Server hech narsani eslab qolmaydi: imzoni tekshirish kifoya.

#Access va refresh tokenlar

Muammo: uzoq muddatli token o'g'irlansa — hujumchi uzoq vaqt foydalanadi; qisqa muddatli bo'lsa — foydalanuvchi har 15 daqiqada qayta login qiladi. Yechim — ikki token:

  • Access token — qisqa muddatli (5–15 daqiqa), har bir API so'rovida ishlatiladi.
  • Refresh token — uzoq muddatli (7–30 kun), faqat /auth/refresh ga yuboriladi va yangi access token olish uchun ishlatiladi. U serverda (bazada) qayd qilinadi — shuning uchun uni bekor qilish (logout, "barcha qurilmalardan chiqish") mumkin.
  • Rotatsiya — har refresh'da eski refresh token bekor qilinib, yangisi beriladi. Eski token qayta ishlatilsa — o'g'irlik belgisi, foydalanuvchining barcha sessiyalari yopiladi.

#Login xavfsizligi bo'yicha qoidalar

  • Umumiy xato xabari: "Email yoki parol noto'g'ri" — "Bunday email yo'q" emas (aks holda hujumchi qaysi emaillar ro'yxatdan o'tganini biladi).
  • Rate limiting: bir IP/akkauntga daqiqada 5–10 urinish (brute-force'ga qarshi).
  • Parol siyosati: kamida 8–12 belgi; murakkablik qoidalaridan ko'ra uzunlik muhimroq; mashhur sizib chiqqan parollarni rad etish.
  • HTTPS — majburiy.
  • Parolni tiklash tokenlari — bir martalik, qisqa muddatli, bazada xesh ko'rinishida.
  • Muhim ilovalar uchun ikki bosqichli autentifikatsiya (2FA): TOTP (Google Authenticator) yoki SMS.
  • Tayyor yechimlar ham bor: OAuth ("Google bilan kirish"), Auth0, Clerk, Supabase Auth, Better Auth. Lekin ular ortidagi tamoyillarni bilish baribir zarur.

import bcrypt from 'bcrypt';
import jwt from 'jsonwebtoken';
import { query } from '../db/pool.js';
import { config } from '../config.js';
import { HttpError } from '../utils/errors.js';

const BCRYPT_COST = 12;
// Foydalanuvchi topilmasa ham bcrypt.compare bajarilishi uchun — javob vaqti bo'yicha email borligini bilib bo'lmasin
const DUMMY_HASH = await bcrypt.hash('dummy-password', BCRYPT_COST);

const publicUser = ({ id, name, email, role }) => ({ id, name, email, role });

export function signAccessToken(user) {
  return jwt.sign(
    { sub: String(user.id), role: user.role, tv: user.token_version },
    config.jwtSecret,
    { expiresIn: config.accessTtl, algorithm: 'HS256' }
  );
}

export async function register({ name, email, password }) {
  const passwordHash = await bcrypt.hash(password, BCRYPT_COST);
  try {
    const { rows: [user] } = await query(
      `INSERT INTO users (name, email, password_hash) VALUES ($1, lower($2), $3)
       RETURNING id, name, email, role, token_version`,
      [name, email, passwordHash]
    );
    return user;
  } catch (err) {
    if (err.code === '23505') throw HttpError.conflict('Bu email bilan ro\'yxatdan o\'tilgan');
    throw err;
  }
}

export async function login({ email, password }) {
  const { rows: [user] } = await query('SELECT * FROM users WHERE email = lower($1)', [email]);
  const ok = await bcrypt.compare(password, user?.password_hash ?? DUMMY_HASH);
  if (!user || !ok) throw HttpError.unauthorized('Email yoki parol noto\'g\'ri');
  return user;
}

export { publicUser };
src/routes/auth.routes.js
import { Router } from 'express';
import { z } from 'zod';
import { validate } from '../middleware/validate.js';
import { requireAuth } from '../middleware/auth.js';
import * as auth from '../services/auth.service.js';
import { config } from '../config.js';
import { rateLimit } from '../middleware/common.js';

const router = Router();

const registerSchema = z.object({
  name: z.string().trim().min(2).max(60),
  email: z.string().trim().email(),
  password: z.string().min(8, 'Parol kamida 8 belgi').max(72),   // bcrypt 72 baytdan keyingisini e'tiborsiz qoldiradi
});
const loginSchema = z.object({ email: z.string().trim().email(), password: z.string().min(1) });

const cookieOptions = {
  httpOnly: true,
  secure: config.isProd,
  sameSite: 'lax',
  maxAge: 15 * 60 * 1000,
};

function sendSession(res, user, status = 200) {
  res.cookie('access_token', auth.signAccessToken(user), cookieOptions);
  res.status(status).json({ user: auth.publicUser(user) });
}

const authLimiter = rateLimit({ windowMs: 15 * 60_000, max: 10 });   // 15 daqiqada 10 urinish

router.post('/register', authLimiter, validate(registerSchema), async (req, res) => {
  const user = await auth.register(req.validated.body);
  sendSession(res, user, 201);
});

router.post('/login', authLimiter, validate(loginSchema), async (req, res) => {
  const user = await auth.login(req.validated.body);
  sendSession(res, user);
});

router.post('/logout', (req, res) => {
  res.clearCookie('access_token', { ...cookieOptions, maxAge: undefined });
  res.status(204).end();
});

router.get('/me', requireAuth, (req, res) => {
  res.json({ user: auth.publicUser(req.user) });
});

export default router;

Himoyalangan marshrutlar va "faqat egasi" tekshiruvi

src/middleware/auth.js
import jwt from 'jsonwebtoken';
import { query } from '../db/pool.js';
import { config } from '../config.js';
import { HttpError } from '../utils/errors.js';

export async function requireAuth(req, res, next) {
  // Cookie (brauzer) yoki Authorization sarlavhasi (mobil ilova, Postman)
  const header = req.get('authorization');
  const token = req.cookies?.access_token
    ?? (header?.startsWith('Bearer ') ? header.slice(7) : null);

  if (!token) return next(HttpError.unauthorized());

  let payload;
  try {
    payload = jwt.verify(token, config.jwtSecret, { algorithms: ['HS256'] }); // algoritmni aniq ko'rsatamiz
  } catch (err) {
    return next(HttpError.unauthorized(
      err.name === 'TokenExpiredError' ? 'Sessiya muddati tugagan' : 'Token yaroqsiz'
    ));
  }

  // Foydalanuvchi o'chirilgan yoki "barcha qurilmalardan chiqish" qilingan bo'lishi mumkin
  const { rows: [user] } = await query(
    'SELECT id, name, email, role, token_version FROM users WHERE id = $1',
    [payload.sub]
  );
  if (!user || user.token_version !== payload.tv) return next(HttpError.unauthorized('Sessiya bekor qilingan'));

  req.user = user;
  next();
}

// Ixtiyoriy autentifikatsiya: mehmon ham kira oladi, lekin login qilgan bo'lsa req.user bo'ladi
export function optionalAuth(req, res, next) {
  if (!req.cookies?.access_token && !req.get('authorization')) return next();
  // Token yaroqsiz bo'lsa ham xato bermaymiz — mehmon sifatida davom etadi
  return requireAuth(req, res, () => next());
}

router.patch('/:id', requireAuth, async (req, res) => {
  const { rows: [post] } = await query('SELECT author_id FROM posts WHERE id = $1', [req.params.id]);
  if (!post) throw HttpError.notFound('Post topilmadi');

  const isOwner = String(post.author_id) === String(req.user.id);
  if (!isOwner && req.user.role !== 'admin') {
    throw HttpError.forbidden('Faqat muallif yoki admin tahrirlay oladi');
  }

  const { rows: [updated] } = await query(
    'UPDATE posts SET title = COALESCE($2, title), body = COALESCE($3, body) WHERE id = $1 RETURNING *',
    [req.params.id, req.body.title, req.body.body]
  );
  res.json(updated);
});

Rollar va ruxsatlar (RBAC)

Har bir rolga emas, har bir ruxsatga tekshirish yozish kodni moslashuvchan qiladi: yangi rol qo'shish faqat jadvalni o'zgartirishni talab qiladi.

src/auth/permissions.js
export const PERMISSIONS = {
  user:   ['post:create', 'post:update:own', 'post:delete:own', 'comment:create'],
  editor: ['post:create', 'post:update:any', 'post:publish', 'comment:create', 'comment:delete:any'],
  admin:  ['*'],                                   // hamma narsa
};

export function can(user, permission) {
  const list = PERMISSIONS[user?.role] ?? [];
  return list.includes('*') || list.includes(permission);
}
src/middleware/authorize.js
import { can } from '../auth/permissions.js';
import { HttpError } from '../utils/errors.js';

export const requirePermission = (...perms) => (req, res, next) => {
  if (!req.user) return next(HttpError.unauthorized());
  if (!perms.some(p => can(req.user, p))) {
    return next(HttpError.forbidden(`Bu amal uchun ruxsat kerak: ${perms.join(' yoki ')}`));
  }
  next();
};

httpOnly cookie ishlatilganda frontend tokenni umuman "ko'rmaydi" — brauzer uni o'zi yuboradi. Faqat credentials: 'include' kerak.

client/auth.js
const API = 'http://localhost:3000/api/v1';

export async function api(path, { method = 'GET', body } = {}) {
  const res = await fetch(API + path, {
    method,
    credentials: 'include',          // 🍪 cookie'ni boshqa origin'dagi API'ga yuborish
    headers: body ? { 'Content-Type': 'application/json' } : {},
    body: body ? JSON.stringify(body) : undefined,
  });

  if (res.status === 401 && path !== '/auth/me' && path !== '/auth/login') {
    // Sessiya tugagan — foydalanuvchini login sahifasiga, qaytish manzili bilan
    location.href = `/login.html?next=${encodeURIComponent(location.pathname)}`;
    return new Promise(() => {});   // yo'naltirish paytida kod davom etmasin
  }

  const data = res.status === 204 ? null : await res.json();
  if (!res.ok) throw Object.assign(new Error(data?.error?.message ?? 'Xatolik'), { status: res.status, data });
  return data;
}

export const auth = {
  me: () => api('/auth/me').then(d => d.user).catch(() => null),
  login: (email, password) => api('/auth/login', { method: 'POST', body: { email, password } }),
  register: (data) => api('/auth/register', { method: 'POST', body: data }),
  logout: () => api('/auth/logout', { method: 'POST' }),
};

🏋️ Mustaqil ish

  1. Refresh token mexanizmini qo'shing: refresh_tokens(id, user_id, token_hash, expires_at, revoked_at) jadvali, POST /auth/refresh (rotatsiya bilan), POST /auth/logout-all.
  2. "Parolni unutdim": POST /auth/forgot bir martalik token yaratib (bazada xeshi bilan, 30 daqiqa muddat) konsolga havola chiqarsin; POST /auth/reset uni tekshirib, parolni almashtirsin va token_version ni oshirsin.
  3. Login urinishlarini login_attempts jadvalida qayd qiling; 5 ta muvaffaqiyatsiz urinishdan keyin akkauntni 15 daqiqaga bloklang.
  4. jwt.io saytida o'z tokeningizni oching va payload'ni o'zgartirib ko'ring. Server uni nega qabul qilmaydi?
  5. GET /api/orders/:id marshrutida IDOR zaifligini ataylab yarating, so'ng uni tuzating va farqni test bilan isbotlang.

✅ Xulosa

  • AuthN — "kimsan?" (401), AuthZ — "nima qila olasan?" (403).
  • Parollar faqat bcrypt/argon2 bilan xeshlangan holda saqlanadi.
  • JWT imzolangan, lekin shifrlanmagan; qisqa muddat + refresh token; algoritmni aniq ko'rsating.
  • Veb-ilovalarda tokenni HttpOnly; Secure; SameSite cookie'da saqlang.
  • Foydalanuvchi ID'si doim tokendan; har bir resursda egalikni tekshiring (IDOR).
  • Ruxsatlar asosidagi RBAC kodni moslashuvchan qiladi; frontend tekshiruvi faqat UX uchun.
